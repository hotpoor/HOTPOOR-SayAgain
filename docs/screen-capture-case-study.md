# 微信窗口捕获问题：从有效对标到本地实现

记录整理：2026-09-25，时间均为北京时间（UTC+8）。本页公开排查思路、时间依据和实现，不收录私人聊天截图、完整应用日志、账号或设备标识。

## 为什么记录这个案例

用户需要把眼前的内容截到剪贴板，供自己粘贴使用。问题不是截图 API 是否返回了图片，而是图片是否包含用户看得到的目标窗口。

我们的思路是选择在相同场景下有成功表现的成熟产品作为对标，再查明可复现的差异。这个案例选择的是远程控制领域的[贝锐向日葵](https://sunlogin.oray.com/)：用户确认它能显示同一微信窗口，给出了继续排查的有效线索。选择行业内成熟产品的价值在于其实际解决了相关问题，而不是仅凭品牌推断技术路线或把单次结果写成行业排名。

## 做过哪些尝试

| 尝试 | 当时结果 | 得到的结论 / 修正 |
| --- | --- | --- |
| 系统 `screencapture` 整屏截图 | 返回图片，但微信窗口没有出现在结果里。 | “有图片”不是“目标内容已捕获”；应检查实际画面。 |
| Python Pillow `ImageGrab.grab()` | 同样遗漏微信。 | 后续确认该环境底层仍调用 `screencapture`，不能当作独立接口复验。 |
| 系统录屏 / QuickTime 入口 | 用户报告录屏也未解决；QuickTime 仅讨论了系统录屏入口。 | 区分用户报告、建议尝试和开发者已执行测试，不能把更换入口计为新技术路线成功。 |
| 屏幕录制权限与窗口枚举 | 权限已开启，可以枚举到微信窗口。 | 问题不止是未授权或窗口不在前台；继续看实际捕获结果。 |
| ScreenCaptureKit 整屏 / 单窗口 | 整屏遗漏微信；单独窗口为黑色。 | 当前配置下未解决。 |
| ScreenCaptureKit 连续流 | 仍未解决。 | 单帧改连续流不足以消除差异。 |
| AVCaptureScreenInput | 探针产生图片，但当轮未确立其为可用解决路径。 | 保留为已尝试，不标成成功，也不凭文件存在推断捕获完整。 |
| 微信“截图时保留当前窗口”设置 | 用户已经开启。 | 该设置针对微信自己的截图行为，未解释外部捕获差异。 |
| 检查向日葵捕获组件与运行日志 | 组件包含多种引擎，运行日志出现 displaystream 会话创建及启动成功。 | 组件符号只代表有这种实现；运行日志提供当时启用路径的进一步证据。 |
| Swift 直接调用 CGDisplayStream | 当前 SDK 编译失败，提示改用 ScreenCaptureKit。 | 区分 SDK 声明不可用与运行时实现是否仍存在。 |
| Objective-C 动态解析 CGDisplayStream | 系统保留符号，独立原型成功捕获微信；紧邻时间的系统截图仍遗漏。 | 找到本机可复现的捕获路径，进而实现产品功能。 |
| Electron 剪贴板集成 | 首次调用与 Electron 44 图片写入 API 不匹配，修正后通过。 | 原型取到图片后，还需要验证实际剪贴板写入及用户粘贴链路。 |
| 双产品共享快捷键 | 加入优先级、独占监听、待命请求确认和冲突回滚，验证交接与重启。 | 从单次原型补齐多应用同时运行时的行为。 |

早期排查曾把现象直接解释为“微信监听并拦截”，也曾过早认为“继续换入口没有意义”。随后根据向日葵的成功表现修正判断：应描述已观察到的窗口遗漏，保留对具体机制的疑问，继续比较真正不同的捕获路径。

## 参考了谁，自己实现了什么

**对标线索来自向日葵的实际成功表现。** 本机组件中发现 ScreenCaptureKit、CGDisplayStream 与 AVCaptureScreenInput 等实现名称；进一步在当时运行日志看到以下最小事件摘要：

```text
2026-09-25 19:02:36.432  [displaystream] createcapturesession
2026-09-25 19:02:36.466  [displaystream] startCapture success
```

日志与独立原型共同支持当次 displaystream 路径判断，不代表向日葵的所有版本、会话都使用同一引擎。本项目没有取得其完整源码，也不分发其二进制、账号配置或完整日志。产品官网用于说明对标对象，具体接口判断来自本机检查，而非厂商公开承诺。

我们根据系统接口编写了独立原生辅助程序，再自行完成 Electron 接入、设置界面、快捷键协作、异常反馈和测试。实际路径为：

```text
用户快捷键 / 截图按钮
→ 选择鼠标所在显示器
→ 检查 macOS 屏幕捕获权限
→ CGDisplayStream → IOSurface → PNG（stdout）
→ Electron 校验图像 → 写入本机剪贴板
```

实现入口：[原生辅助程序](../desktop/screenshot/native/capture.m)、[Electron 接入](../desktop/screenshot/index.cjs)、[跨应用协调](../desktop/screenshot/coordinator.cjs)、[快捷键及测试](../desktop/screenshot/shortcut.test.cjs)。编译、使用与打包说明见 [截图功能说明](screen-capture.md)。复用排查方法见 [截图排查 Skill](../skills/screen-capture-troubleshooting/SKILL.md)。

## 有效时间与适用环境

这是一项有版本边界的兼容方案，没有可以承诺的固定有效期。成功实测日期为 **2026-09-25**，环境为 **macOS 26.5.2（25F84）/ Apple Silicon**。整理时读取的本机版本为微信 **4.1.13（269631）**、向日葵 **16.5.0（30905）**；这是整理时版本快照，初次试验没有单独锁定应用安装包指纹。双产品使用 Electron 44，SayAgain 为 44.4.5。

Apple 已将 [CGDisplayStream](https://developer.apple.com/documentation/coregraphics/cgdisplaystream) 标为弃用，推荐使用 [ScreenCaptureKit](https://developer.apple.com/documentation/screencapturekit)。当日 SDK 拒绝直接调用旧接口，但该系统运行时仍保留兼容符号。因此实现采用动态解析；这不是对未来 macOS 的兼容保证，也不能推广为可捕获所有受保护内容。

系统、微信、Electron、签名或权限发生变化后，应重做同窗口、相邻时间的内容对照。若权限不足、符号消失、超时或图像无效，当前实现明确报错并保留原剪贴板，不静默换成已知可能遗漏窗口的路径。图片非空仍不能自动证明目标窗口完整，升级后需要内容核验。Windows/Linux 使用 Electron desktopCapturer，本次未验证它们对微信的同类问题。

截图功能本身只写本机剪贴板，不执行 OCR、上传或自动发送；后续粘贴目的地由用户决定。原始私密画面与完整诊断记录不进入公开仓库。
