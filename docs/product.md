# 产品与本地流程 v0.1

状态：首版设计。ID 使用 UUID v4 去连字符后的 32 位小写十六进制格式，采用三个 SQLite 库和实体分库单表结构。优先推荐本地运行，空间不足时提供 Qwen 云端接入；客户端选用 Electron。

## 两套服务

Local 的评估由用户自带客户端完成，SayAgain 提供 Skill、可验证的写入接口、本地应用和 TTS worker。它不等于“所有推理均离线”：Codex / Claude Code 的语言评估仍可能经过用户选择的云模型；本地录音与合成默认不上传。完全离线评估可通过之后的本地评估器适配。

本地空间足够时仍推荐本地；不足时明确提示无法安装，并在设置顶部提供 Qwen AK 输入及平台链接。用户主动启用后，云端仅接收所选参考录音与待合成文字，不自动同步数据库。

## 首次使用

1. 选择母语（解释与译文语言）、目标语言（练习语言），界面语言单独设置。
2. 建立学习配置，可建立多个语言对并切换；每条历史表达保留当时语言对。
3. 选择客户端、启用的对话范围、每轮评估策略和建议严格程度。
4. 检测硬件、磁盘和模型运行环境，显示下载大小和所选模型；由用户在客户端安装流程中确认下载。
5. 录制或导入自己的音色样本，填写名称、备注、录音语言和准确转写，试听参考录音后保存。
6. 默认先完成表达评估，音频按需合成；用户可开启“新建议自动生成选中音色”的队列模式。

## 模型与音色

Qwen3-TTS 的 Base 0.6B / 1.7B 用于参考音频克隆；CustomVoice 是预设音色，不应当作为“我的音色”克隆模型。官方模型目前列出 10 种语言，产品的语言字段不受此列表限制，但合成前必须按当前 provider 能力检测，不支持时明确显示“可练习文本，当前引擎不支持此语言”。不能宣称支持任意语言合成。

官方示例以 Python / PyTorch 为主，安装器要记录 backend、设备、dtype、权重 revision、校验信息与安装状态。CPU / CUDA / Apple Silicon 的可运行性与性能需分别验证，不能仅根据芯片名称承诺实时。建议先提供低资源档与质量档选择；本阶段不下载权重。

音色库分为 `voice`（一个可命名的个人音色）和 `voice_sample`（其录音素材）。用户可以创建多个独立音色，也可为同一音色录制多个样本；一次合成明确选择一个样本/已构建的克隆提示，不假定所有模型支持多段样本自动融合。

每个音色保存名称、备注、创建日期、修改日期、归档时间、默认样本和版本。参考录音和提取的克隆提示是文件资产；克隆提示的格式与模型绑定，模型升级后可重新构建，不等于训练一份独立大模型。

归档保留历史、录音和已生成音频，并从默认选择器隐藏。若归档的是某语言对的默认音色，将默认值清空并提示重新选择，不能悄悄替换声音。归档后排队但尚未开始的新合成取消/暂停；正在运行的结果可保留为历史，但不得重新成为默认。支持恢复归档；删除是另一项操作。

## 每轮对话评估

“每轮”定义为已启用对话中的一条最终用户消息；流式片段不重复评估。客户端适配器以 `client + conversation + turn + message_revision` 标识事件。评估策略版本、学习配置版本和目标语言加入幂等键；重试不重复生成表达，显式重新评估形成新记录并指向旧版本。

Skill 说明如何评估和保存；可靠触发需要适配器收到客户端事件或明确调用。Skill 的相关性自动选择不能当作“每条消息必达”的保障。各宿主的触发、文本获取范围和回执需分别实现/验证；没有自动事件能力的宿主标记为手动/尽力接入，不伪称自动覆盖。仅处理启用范围内的用户原创表达，不把助手回答、代码或引用资料当成用户的语言水平。

每次评估保留一种结果：

- `needs_improvement`：有具体可解释的改进，生成一条或多条 expression。
- `no_change`：表达已经合适，不强行制造建议。
- `skipped`：没有练习语言表达、只有代码/引用、内容过短等，记录原因。
- `uncertain`：疑似转写错误或原意不清，等待用户确认，不直接编造纠正。
- `failed`：客户端/模型/协议失败，可重试。

默认后台处理，不打断用户主任务；界面只提示新增条数。母语消息可记录 skipped；可选“帮我用目标语言表达”模式，但必须标为翻译练习，不称为纠错。语音输入需要独立 ASR 适配器或宿主提供转写，Qwen3-TTS 本身不负责语音识别。

每条建议保存精确原句及消息内范围、优化表达、母语解释、翻译、可复用句型、类别、置信度及原始来源。区分语法错误与可选风格改写；识别不确定片段应保留待确认状态。存来源片段和必要上下文，完整会话存档作为独立可选设置。

桌面采用 Electron，页面功能参考 Nexplay 线上版，UI 尽量参考 Codex 和 ChatGPT 客户端。具体布局和职责划分见 [客户端设计](desktop.md)；基础桌面应用已实现，自动评估与 TTS 仍处于设计阶段；以 README 的进度表为准。

| 页面 | 需要显示/配置 |
| --- | --- |
| 表达回顾 | 语言对、日期/来源筛选、搜索、排序；原句/建议/母语译文；修改说明、可复用句型；来源发生时间和建议创建时间；采纳、忽略、收藏、归档 |
| 听与练 | 多音色选择；生成/排队/失败/重试；朗读、暂停、慢速；默认展开波形；回放状态与练习次数 |
| 音色库 | 名称、备注、创建日期、参考录音试听、样本语言/时长、默认样本、模型准备状态；按 active/archived 分组，恢复归档 |

UI 沿用已确认风格：白底黑白灰、无最外层卡片框、段落大留白、浅灰标签、双栏中间细竖线；窄屏单栏，修改原因和句型用标题/留白分组，不嵌套多层卡片。点击波形无额外框，键盘操作有焦点提示。布局断点和窗口全屏属于显示状态，不改变数据模型。

## 成本与性能

同一文本版本、语言、音色版本、样本 hash、模型 revision 和合成参数命中缓存时复用音频。仅备注/归档等元数据变化不使音频缓存失效；影响声音的样本/模型变化增加 `voice_revision`。普通慢放使用客户端播放速度，不重新调用 TTS。生成完成提取 duration 与 waveform，打开页面只读波形元数据，点击朗读才加载音频。

评估不能阻塞主对话，音频不能阻塞评估。任务记录 queued/running/succeeded/failed/cancelled，支持进程重启后的租约恢复。模型下载、音色准备和合成是不同任务。

## 参考与实施顺序

1. 三库初始化、统一实体存取、索引一致性与备份。
2. 语言配置、音色录制/备注/归档和文件资产管理。
3. 手动导入对话的评估协议与 Skill，先验证 no_change/uncertain/去重。
4. Qwen3-TTS 本地 worker、缓存、波形与播放。
5. 各客户端每轮触发适配，逐个验证覆盖率。
云端服务不在当前实施范围。
