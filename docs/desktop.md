# Electron 客户端设计

状态：已确定技术与设计方向，尚未开始桌面运行代码。本文描述实施目标，不表示已有可下载客户端。

## 参考与延续

页面功能和内容展示参考现有 Nexplay 线上原型（page ID：`01018b5b68074b5e81e3e667ebaefd1f`），包括原句、自然表达、母语译文、修改原因、句型、我的音色、朗读和慢速回放。公开示例使用虚构内容，不直接复制原型里的私人对话、录音或访问凭据。

桌面 UI 尽量参考 Codex 和 ChatGPT 客户端的简洁布局、侧栏导航、阅读宽度和低干扰控件。使用 HOTPOOR SayAgain 品牌；此前确认的布局取舍继续适用。

## 页面结构

- 侧栏：表达回顾、音色库，底部放语言与应用设置；可收起，为窄窗口保留空间。
- 表达回顾：顶部搜索、语言对与时间筛选，正文显示原句、建议、译文和来源时间；解释及听练在宽窗口右侧呈现。
- 音色库：录制或导入、多样本试听、名称和备注、创建日期、默认样本、归档与恢复。
- 设置：母语与目标语言、客户端接入范围、本地模型路径与状态、音频与备份策略。
- 全屏：明显的进入/退出入口，支持键盘退出；窗口状态与学习数据分开保存。

## 视觉与交互约定

使用黑白灰基础色、浅灰标签底色和轻量边框。条目无最外层卡片框，条目之间增加留白；宽窗口左右栏之间有细竖线，窄窗口改为单栏。修改原因与句型紧随对应表达，使用标题、缩进和间距区分，不叠加多层盒子。

音轨默认展开，波形与播放状态保持稳定，点击不会突然多出边框；保留键盘可见焦点。区分尚未生成、排队、生成中、可播放和失败，避免将所有状态都显示成可播放按钮。浅色优先，深色主题后续统一验证。

## Electron 与本地服务职责

以下为待实现的边界约定：

| 部分 | 职责 |
| --- | --- |
| Electron 主进程 | 窗口、文件选择、应用目录、本地服务生命周期 |
| preload 接口 | 提供有限的业务操作接口，校验调用参数 |
| 页面 | 表达回顾、音色录制与试听、设置及任务状态；不直接执行 SQL 或系统命令 |
| 存储服务 | 统一读写三库、维护索引和任务状态、备份恢复 |
| TTS worker | 独立执行模型加载、音色准备与合成，避免阻塞页面 |
| Skill / 客户端适配器 | 提交对话评估结果并接收回执，使用相同数据协议 |

桌面运行本地页面，不直接将线上网站嵌入为应用主体。模型环境独立管理；Electron 技术选择不意味着 UI 需要依赖 Python 实现。具体 SQLite 驱动、前端框架与打包工具在实现阶段验证后确定。
