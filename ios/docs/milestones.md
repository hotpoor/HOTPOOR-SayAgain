# SayAgain iOS 阶段成果

本文件在 2026-09-27 整理，回顾已发生的开发，不将整理时间当成实现耗时。

## 1. 从能启动到真实产品流程

- iPad mini 3 / iOS 12.5.8 上运行原生 UIKit 客户端。
- 账号独立配置：service-inference 管理 AK 与使用 AK 匹配；千问支持多个账号，语音合成使用 TTS 链路。
- 模型选择、全局音量与字号；音色独立录制和约 30 秒中文参考稿。
- 表达回顾按 Electron 实际截图重新布局，补真实 PCM 波形、播放进度与跳转。

保留用户反馈：初版界面过于简陋，表达回顾布局、声音模型选择、音量/字号和波形缺失，不能因后续修复抹去。现有功能的实现与自动验证不等同于用户已认可整个界面。详细范围和证据见 [validation.md](validation.md)。

## 2. iPad 本机模型的第一项真机结果

2026-09-26 晚间在用户已有录音上完成前 10 秒 SenseVoice INT8 本机识别：

| 指标 | 实测 |
|---|---:|
| 音频 | 10.00 秒 |
| 模型加载 | 22.55 秒 |
| 推理 | 15.66 秒 |
| 总耗时 | 40.50 秒 |
| 100ms 采样的进程物理内存峰值 | 301.3 MiB |
| 设备物理内存 | 970 MiB |

使用与 Electron 相同来源的模型权重，换为 sherpa-onnx + ONNX Runtime 原生运行；没有把 Electron/Python 直接装进 iPad。权重指纹在 `native/model-manifest.json`，构建过程在 [native/README.md](../native/README.md)。原录音和原文字未被改写。

这只证明本地 ASR；不是 Qwen 克隆 TTS、说话人识别或整个桌面管线完成移植。代码不上传录音，但尚未做飞行模式验收。

## 3. 整条录音与发行路线

整条录音实现采用约 7–10 秒缓冲，低能量窗口优先切段；模型只加载一次，每段完成即原子保存独立 JSON 草稿。停止在当前步骤结束后生效；重新打开录音能读取草稿，采用时先填入编辑框供校对，再由用户保存。

切段属于能量启发式，并非 Silero VAD 或逐词对齐；连续语音的段边界仍可能截词。时间是输入片段范围，不是精准字幕时间。识别期间临时防止自动锁屏，结束后恢复原设置；进入后台请求停止，不保证后台持续运行，不做断点续算、不识别说话人。JSON 备份目前不包含旁路 ASR 草稿；通过文件共享备份完整 Documents 可保留。

旧设备与现代发行版在 `Config/` 分开，仍共享源码。现代 Xcode 26.6 / SDK 26.5 的 iOS 15 Release 无签名编译已通过。真机完整处理 241.42 秒录音、29 段：加载 25.03 秒、推理 640.31 秒、总耗时 811.08 秒（约 13.5 分钟），采样内存峰值 311.6 MiB。重启恢复草稿与原文字不变的断言均通过；另验证了模型加载期间取消新任务，旧完整草稿和原文仍保留。每条录音当前只有一份 ASR 草稿，不保留多轮识别历史。速度尚未达到实时，详见 [validation.md](validation.md)。

苹果现行与未来要求、可复现命令见 [distribution.md](distribution.md)。没有执行 App Store 上传或发布。
